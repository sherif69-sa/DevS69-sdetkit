# Changelog

## Unreleased

- **The repo-audit action (`.github/actions/repo-audit`) works in other repositories.**
  - **Install:** it used to run `pip install -e "$GITHUB_WORKSPACE"` whenever the workspace had a `pyproject.toml`. In any other Python repository that installed the audited project instead of sdetkit, so the `sdetkit repo audit` that followed was not found. It now installs sdetkit from the action's own source into a separate virtual environment; the new `sdetkit_version` input installs a PyPI release instead.
  - **Checkout and pinning:** it no longer checks the repository out a second time, and its setup-python, upload-sarif and upload-artifact steps are pinned to commit SHAs.
  - **Runs:** it runs the audit three times instead of four.
  - **After a failed audit:** the summary and SARIF upload still run.
  - **Docs:** `docs/github-action.md` shows `uses: sherif69-sa/DevS69-sdetkit/.github/actions/repo-audit@v2.0.0` after a checkout, corrects the install description, and says when to use it rather than the gate action.

- **Repositories without `pyproject.toml`.** `gate fast` no longer reads NO_SHIP in an empty repository, or in a Go, JavaScript or Rust repository whose own tests pass, just because it has no `pyproject.toml`.
  - **Before:** doctor failed its high-severity pyproject check with "pyproject.toml is missing" and advised "Fix pyproject.toml syntax."
  - **Now:** doctor skips the check when the repository has no Python project, and passes with a suggestion when `setup.py` or `setup.cfg` declares one. Only an unparseable `pyproject.toml` still fails.
  - **Nothing to check:** when detection finds no tests (Python or other) and no ruff or mypy configuration, the verdict is `NOT_RUN` (exit 0) instead of `SHIP`, with the next action "Add tests …, or configure ruff or mypy". A suite the caller leaves out with `--no-tests` or `--skip` does not trigger this, and neither does the `adoption` profile.
  - **Markdown summary:** the `**Next:**` line now uses the verdict's next action.
- **Security:** `sdetkit serve` and `sdetkit ops serve` now need a bearer token on every request except the health check.
  - **The problem:** both servers listened on 127.0.0.1 with no authentication. Any web page open in the user's browser could send them a cross-site POST. Through `ops serve`'s `/run-action`, such a request could write `report.build` output to any path, including outside the working directory.
  - **Token:** each server prints a fresh token at start-up. `SDETKIT_SERVER_TOKEN` sets it instead.
  - **Host check:** a server on loopback refuses requests addressed to other host names, which stops DNS rebinding.
  - **Other interfaces:** binding to a non-loopback interface needs `--allow-remote`.
  - **Paths:** `/run-action` keeps its `root`, `repo_root` and `output` inputs inside the server's working directory.
  - **Code:** the shared guard is `sdetkit.local_http`.

- New GitHub Action: `uses: sherif69-sa/DevS69-sdetkit@v2.0.0` runs `gate fast` on a pull request. It writes the verdict to the job summary, posts it as one pull request comment that later runs update, and fails the step on the verdicts in `fail-on` (default `NO_SHIP,NOT_RUN`). The action installs sdetkit in its own virtual environment from the action's source and runs the repository's checks in the project's environment (`.venv`, Poetry, Pipenv, else the job's `python`). On a fork, where the token cannot comment, it warns instead of failing. Outputs: `verdict`, `report` and `summary`. The new `Gate action (self)` CI job runs it on this repository. See `docs/gate-action.md`.
- `gate fast --format md` leads with the verdict (`SHIP`, `REVIEW`, `NOT_RUN` or `NO_SHIP`) and what it means, then gives a table of steps (passed, failed, not run because of the environment, skipped), the first failure and the next command. It no longer prints the repository's absolute path. The new `gate fast --summary-out PATH` also appends this summary to a file, for example `$GITHUB_STEP_SUMMARY`.

## [2.0.0]

Release candidate scope established: 2026-10-15. Not yet tagged or published; release qualification, external publishing configuration and public verification remain pending.

### Highlights

- **A smaller, connected CLI.** About 40 commands in four groups instead of 191; `gate fast` works in any repository and reads it through one repository model (`sdetkit.repo_model.v1`).
- **One verdict.** `gate fast`, `gate release`, `mission-control run`, `release-room plan` and `diagnose run` emit the same `sdetkit.verdict.v1` (`SHIP`, `REVIEW`, `NOT_RUN`, `NO_SHIP`), and green steps that proved nothing read `NOT_RUN`, never `SHIP`.
- **From a failing gate to a reviewed fix.** `diagnose run` diagnoses the latest failing gate run (or saved CI logs), proves the narrowest mechanical fix in a throwaway copy, and ends with a decision card that `diagnose decide` records. Nothing is applied for you.
- **Memory that accumulates.** RepoMemory records every attempt and feeds proven fix patterns back to the patch scorer.
- **Checks in the project's own environment.** `gate fast` runs ruff, mypy and pytest with the repository's own interpreter and the way its pre-commit hooks and `tox.ini` run them; a failure that comes from the environment reads `NOT_RUN` with the setup command, not `NO_SHIP`. Seven open-source projects prove it in `docs/external-repo-proof.md`.
- **A clean first run.** Repeated gate runs no longer block on SDETKit's own outputs, every command recognises uv, Poetry, PDM and Pipenv locks, and `repo` subcommands accept any repository root.

### Upgrading from 1.2

- **Removed commands.** The hidden playbook, closeout, phase and `legacy` namespace commands, `start`, `onboarding`, `agent`, `author`, the KPI, professional-naming, PR-quality and security-disposition report commands, and the `--show-hidden` and `--no-legacy-hint` flags are gone. `python -m sdetkit --help` and `docs/cli.md` list what remains; the release decision path (`gate fast`, `gate release`, `doctor`) is unchanged.
- **`gate release`** runs three steps (`doctor --release`, security scan, `gate fast`). Drop any `--playbooks-*` or `--playbook-name` flags from scripts and CI.
- **Imports.** Code that imported a removed `sdetkit.phase*` alias should import the canonical module (`sdetkit.baseline_*`, `sdetkit.release_readiness_*`, `sdetkit.platform_readiness_*`, `sdetkit.readiness_boost`). Importing `sdetkit` no longer patches `builtins`, `argparse` or `pathlib`.
- **Console scripts** `sdetkit-diagnostic-queue-runner`, `sdetkit-local-diagnostic-queue-dashboard`, `sdetkit-adoption-learning-report-dashboard` and `sdetkit-maintenance-queue-rollup-dashboard` are removed.
- **`sdetkit init`** defaults to the `enterprise_python` preset and writes by default; use `--dry-run` to preview.
- **Release readiness** no longer asks for both `requirements.lock` and `poetry.lock`; any one supported lockfile is enough.
- Every authority flag stays `false`: no command applies patches, merges, or dismisses findings on its own.

Approving applies nothing. Decisions are appended to RepoMemory, and a surface people rejected twice is held for review like one the verifier blocked twice. `docs/remediation-loop.md` shows how to post the card on a pull request without giving the pull request's code a write token.

- Adoption-surface discovery walks the repository once instead of once per file pattern (about 16x faster on this repository: 7.1s to 0.44s), and no longer counts `fixtures` directories as part of the repository, so test-data repositories no longer make SDETKit look like a C++ project.
- RepoMemory: `diagnose run` appends every attempt to `.sdetkit/memory/trajectories.jsonl` (`--memory`, `--no-memory`) and feeds the history to the patch scorer. A fix pattern verified twice is no longer penalised as unproven; a surface whose fixes were blocked twice is held for review. New `sdetkit diagnose memory [profile|insights|query]` shows what the history has proven, and `diagnose history --append` adds to a trajectory file instead of replacing it.
- One verdict contract (`sdetkit.verdict.v1`: `SHIP`, `REVIEW`, `NOT_RUN`, `NO_SHIP`) is now emitted by `gate fast`, `gate release`, `mission-control run`, `release-room plan` and `diagnose run`, alongside their existing decision fields. Gate results also record `provenance` (HEAD commit and whether the tree was clean).
- `gate release --reuse-fast <gate-fast.json>` reuses an earlier `gate fast` result when it was recorded on the current commit with a clean tree, instead of running gate fast (and its doctor run) again; the release workflows now pass it.
- `verify merge --evidence <artifact>` folds upstream verdicts into merge readiness: the most severe verdict decides, so green required checks no longer hide a failed gate or a blocked remediation.
- New `sdetkit diagnose run`: the local remediation loop. From saved CI logs it extracts, classifies, plans and records the SafetyGate decision; with `--prove` it applies the narrowest mechanical fix (ruff format or ruff check --fix, limited to the SafetyGate's files) in a throwaway copy, scores the diff, runs the plan's proof in a second isolated copy, asks the independent verifier, appends a trajectory and binds every stage into a protected proof chain. Decisions: `verified_candidate`, `blocked_review_first`, `no_change` (stale log or already fixed), `proof_not_run`, `review_first`.
